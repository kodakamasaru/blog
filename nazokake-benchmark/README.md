# AIの性能差は「なぞかけ」で一発でわかる

## はじめに

最近気づいたのですが、AIに「なぞかけ」を作らせると、モデルの性能差が驚くほどはっきり出ます。
Claude の Haiku / Sonnet / Opus で試したり、effort（思考量）を切り替えたりしてみたところ、きれいに性能順にうまくなりました。

ベンチマークの数字と違って、出力を見れば誰でも一瞬で良し悪しがわかります。
しかもプロンプトは1行、1回試すのに数十秒です。
今回は、Claude・ChatGPT・Grok に同じお題でなぞかけを作らせて、回答をそのまま並べてみました。

なお、Claude の3モデルになぞかけを作らせて比べた記事は既にあります（[参考](#参考)の1つ目）。
そちらは1つのお題で10本ずつ作らせ、「掛詞の深さ」に差が出ると分析したものです。
本記事は、**同音異義語の探し方を3段階の物差しにして、他社モデルや effort の違いまで同じ物差しで並べる**ところが違います。

## なぞかけの3段階

なぞかけは「〇〇とかけて××ととく、そのこころは△△」という言葉遊びです。
△△に同音異義語（または二つの意味を持つ言葉）を入れて、〇〇と××の両方につなげます。

試しているうちに、AIの回答は次の3段階に分かれることに気づきました。

| 段階 | 特徴 |
|---|---|
| 1. 形式だけ | 「とかけて」「ととく」の型はなぞるが、同音異義になっていない。ただの比喩や「あるある」になる |
| 2. お題の読みをそのまま | 同音異義語を探しに行くが、お題の読みと同じ音の言葉をそのまま探す。苦しい文章になりがち |
| 3. 連想を一段挟む | お題から連想した言葉の同音異義語でつなぐ。日本語として自然 |

段階3は、人間がなぞかけを作るときの手順そのものです。
お題から意味で連想してから、その言葉のもう一つの意味で××を探します。
意味の連想と音の一致という、性質の違う2つの条件を同時に満たす必要があるので、多段の推論になります。

## 検証方法

- プロンプト：`「会議」でなぞかけを1つ作ってください。`（手順やコツは一切教えない）
- 回数：各モデル1回だけ（打率ではなく、1発目を見る）
- Claude：Claude Code の CLI（`claude -p`）で、ツールなし、システムプロンプトは `You are a helpful assistant.` のみ。effort は `--effort` で切り替え
- ChatGPT / Grok：Web版の無料プラン。毎回新しいチャットで送信
  - ChatGPT は「思考」ボタンのオン・オフだけ切り替えられたので、両方試しました。モデル名は、回答の再生成メニューに表示されたものです
  - Grok の無料プランで選べるのは「ファスト」のみでした（他のモードは有料プランが必要）
- 実施日：2026年10月19日

```bash
# Claude の実行例
claude -p --model claude-opus-5-5 --effort max --tools= \
  --system-prompt "You are a helpful assistant." \
  "「会議」でなぞかけを1つ作ってください。"
```

お題は「バグ」「月曜日」でも試しましたが、一番差がわかりやすかった「会議」の結果を載せます。
「会議」は「懐疑」のように読みのダジャレに逃げられるので、段階2が出やすく、3段階の違いがよく見えます。

## 結果

回答は、見出し記号などを除いてそのまま載せています。おおむね性能が低い順です。

**判定：1**　Opus でも effort が低いと比喩止まりでした。

> 「会議」とかけて、「お寿司屋さん」と解く。

**判定：3**　同じ Sonnet 4.6 でも、effort を上げると「ネタ」の二つの意味でつなげられました。

> **問題：** 会議とかけて、のびたラーメンと解く。

**判定：3**　「会議がのびる／麺がのびる」で成立しています。Haiku も世代が上がると届くようになりました。

> 「会議」とかけまして「髪型（かみがた）」と解きます。
>
> その心は……
>

>
> （会議がまとまる／髪型がまとまる、の掛けことばです😊）

**判定：3**　low の「トンネル」から一段上がりました。

### Claude Opus 5.5（effort: low）

> **「会議」とかけて、「寝起きの長い髪」と解きます。**
>
> **その心は、どちらも「長いほどまとまらない」でしょう。**

**判定：3**　effort が low でも段階3です。「長いほど」まで両方にかかっていて、Opus 4.8（max）より一歩踏み込んでいます。

### Claude Opus 5.5（effort: max）

> **「会議」とかけまして「鍋料理」と解きます。**
>
> **その心は、どちらも「煮詰まって」きたら「しめ」に入ります。**
>
> - **会議**：議論が煮詰まったら、締め（まとめ）に入る
> - **鍋料理**：スープが煮詰まったら、〆（雑炊やうどん）に入る

**判定：3**　「煮詰まる」と「しめ」の二つを掛けていて、文句なしの出来です。

## 結果から言えること

- **effort を上げると、はっきりうまくなりました。** Sonnet 4.6 は low の段階2から high の段階3へ、Opus 4.8 は low の段階1から max の段階3へ上がっています。
- **Opus 5.5 は low でも段階3でした。** max との差は、掛ける言葉の数や自然さに出ています。
- **新しいモデルほど上、とは限りません。** Sonnet 5 は、effort を high にしても Sonnet 4.6（high）に届きませんでした。ただし1回ずつの生成なので、ここは断定できません。
- **無料版の ChatGPT と Grok は、なぞかけ自体が成立しませんでした。** ChatGPT は思考をオンにしても変わりませんでした。

「バグ」「月曜日」でも傾向は同じで、Opus 4.8（max）と Opus 5.5 は3問とも段階3、ChatGPT と Grok の無料版は3問とも段階1以下でした。

## なぜ差が出るのか

LLM は文章を「トークン」という単位で扱います。
「会議」と「懐疑」はトークンとしては別物で、読みが同じ「かいぎ」だという情報は、文字列からは直接見えません。
同音異義語を探すには、漢字の読みの知識をモデルの内部から引き出す必要があります。

さらに段階3では、その前に「お題から連想される言葉」を探す必要があります。

1. お題から連想される言葉を挙げる（会議 → 煮詰まる、まとまる、長引く……）
2. その言葉に、別の意味や同じ音の別の言葉があるか調べる（煮詰まる → 鍋）
3. 2で見つけた意味から××を決め、文章として自然にまとめる

意味の連想と、音の一致と、文章の自然さを同時に満たす必要があり、どこか1つでも手を抜くと段階が下がります。
性能の低いモデルほど、1を飛ばして段階2になったり、2を飛ばして段階1になったりする、と考えるとわかりやすいです。
この手順は、2005年のなぞかけ自動生成の研究でも「お題 → 関連語 → 同音語 → 答え」として定式化されています（[参考](#参考)）。

## お手軽ベンチマークとして使うコツ

- **手順を教えない。** 「同音異義語を使って」などと書くと、段階1のモデルも段階2までは上がってしまい、差が見えにくくなります。
- **お題は、読みのダジャレに逃げられる単語にする。** 「会議（懐疑）」のように逃げ道があると、段階2で止まるモデルと、段階3まで行けるモデルの違いがはっきりします。
- **1回で決めない。** 下位モデルがたまたま当たることもあるので、お題を2〜3個にするのがおすすめです。

## まとめ

なぞかけは、プロンプト1行・数十秒で、モデルの日本語の言葉遊びの力が一目でわかる、お手軽なベンチマークになりました。
「形式だけ／お題の読みをそのまま／連想を一段挟む」の3段階で見ると、モデルの世代や effort の違いまで同じ物差しで比べられます。
新しいモデルが出たときに、まず「会議でなぞかけを1つ作って」と頼んでみると面白いと思います。
